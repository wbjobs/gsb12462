# 本地审批流状态机模拟器

无框架、无构建步骤的原生 Web 应用，用于在本地模拟多角色审批流和复杂状态流转。

## 运行

```bash
python3 -m http.server 8000
```

然后打开 `http://localhost:8000/`。推荐使用 Chrome、Edge 或 Firefox 的最近版本。

## 流程与角色

- 申请人：张三、李四，可创建、编辑、提交、撤回自己的申请。
- 直属经理：陈经理、周经理，处理经理审批，可同角色转交。
- 部门总监：王总监，处理总监审批。
- 财务：赵财务、钱财务，处理财务复核。

固定步骤为：`草稿填写 -> 经理审批 -> 总监审批 -> 财务复核`。

## 流转规则

- 提交：只有申请人在草稿/退回草稿中可提交，表单必须通过校验。
- 审批通过：只有当前步骤对应角色可执行；转交后只有目标处理人可执行。
- 驳回：必须填写意见，只能回到相邻上一步；表单数据、历史事件和已处理时间均保留。
- 转交：只能转交给同角色的其他用户；状态节点和实例状态不变。
- 撤回：申请人可在审批中，或被退回到草稿后撤回，撤回后进入终态。
- 终态：已通过、已撤回不可继续流转，非法操作会被 Worker 拒绝。

## 实现要点

- `worker.js`：状态机、命令校验、事件 reducer、IndexedDB、v1 迁移和未来版本只读降级。
- `app.js`：DOM 渲染、用户操作、Canvas 图和状态回放控制。
- `index.html` / `styles.css`：页面结构和响应式样式。
- IndexedDB 保存事件日志和当前快照；快照始终可以由事件日志重建。
- 每个实例使用独立 ID 和独立事件数组，状态更新按单条记录事务写入，不共享可变状态。
- “从事件重放”可逐帧查看任意事件后的状态，并校验重放快照是否与存储快照一致。
- “导入 v1 示例”会把旧字段和中文步骤名迁移到 schema v2；“导入未来版本”会以只读方式降级展示。
- “清空存储”只删除实例数据，刷新或重新新建后仍可继续使用。

## 验收对照

- 非法流转：Worker 返回明确错误码和提示，不写入事件。
- 驳回保留：申请数据保留，上一步重新成为当前节点。
- 转交/撤回：转交不改变节点，撤回进入安全终态。
- 多实例并行：实例列表可并行打开，事件和快照按实例隔离。
- 状态回放：逐帧展示状态 JSON，Canvas 同步显示当时节点。
- 版本兼容：v1 自动迁移；高版本只读降级且禁止写入。
- 状态图：Canvas 展示正向、驳回、撤回和同角色转交关系。
